# 如果给你5块钱，你会怎么创业？我先给AI装了个电表

> 历史文章，保留 v0.1.1 时的开发经历，不代表当前版本状态。当前版本及验证范围请看 [README](../README.zh-CN.md) 与 [运行时证据](store-evidence.md)。

如果给我5块钱，让我想一个“创业项目”，我会先做什么？这是一个假设，不是我的实际投入记录，更不是一份赚钱战报。我想先解决一个很小的问题：用AI的时候，能不能少一点猜测，多一点看得见的用量信息？

于是有了用量小窗（USEAGE WINDOW），一个给DeepSeek Harness（DSH）用的插件。说它是“电表”，只是个比喻：把原本需要另找入口查看的信息，放进一个随手能打开的小窗口。

## 我想看的，不只是一串数字

最初的要求很直接：“可以有一个小窗口可以显示……USAGE还剩多少，和下一次重置时间的提示。”

这一版的范围也很明确：Claude、Codex订阅，以及DeepSeek API。订阅关心的是额度用了多少、何时重置；API关心的是今日用量和余额。两种信息不能混成同一笔账。我当时特别要求：“如果是订阅模型，不显示余额和今日消耗钱数。”

所以，“电表”不等于账单，更不等于省钱承诺。用量小窗不是成本限额器，不会替你阻止超支，也不是自动路由器，不会替你挑模型。它做的是展示信息，把判断留给使用者。

## 第一次点击，故事才真正开始

窗口出现以后，我很快发现，做出一个面板和做出一个愿意长期留在屏幕上的工具，是两回事。

我希望最小化时尽量少占地方，还要有一个明显、吸引人点击的展开按钮。可真正点击之后，我留下的反馈却是：“点击了，无法打开。”

这比任何漂亮的功能清单都具体。一个用量窗口，如果缩小后找不回来，就已经打断了使用。我随后把需求改得更朴素：不要另造复杂入口，就让原来的窗口收起来，保留插件名称和展开按钮。先让人看得懂、点得开，再谈好不好看。

## 右下角对了，不代表四个角都对

接着是位置。我希望窗口能缩向屏幕的四个角落，展开时则从所在角落向屏幕中间展开，而不是继续往边缘挤。

听起来只是一个小动作，实际反馈却是：“右下角的做法对了，其他地方的显示UI有问题。”这让我更在意那些不在默认位置上的使用方式：只把最顺手的一种摆法做好，还不够。

同一条反馈里，我也提出了另一个要求：“把插件的资源消耗控制到最小。”监控工具不该为了提醒用量，反过来成为新的负担。不过，这是一项目标，不是我已经拿到的零开销结论。

## 小工具，也要把开关交还给人

我还希望它能放进DSH设置里，让我自己调用或开关。最初做完时，我明确要求不要立刻重启DSH，等下次启动再启用。对我来说，工具应该适应正在进行的工作，而不是要求工作为它让路。

项目和v0.1.1现已在GitHub公开。把它拿出来分享时，我更愿意讲清楚边界：当前公开版本验证的是单元测试和打包检查，不代表所有角落的UI问题都已解决，也不代表已经完成跨浏览器验证。界面是否顺手，仍需要在真实使用里继续确认。

如果你也在DSH里使用这些模型，可以看看项目，尤其欢迎反馈缩小后能否重新展开、四角布局是否合理，以及空闲时的资源占用。与其先许诺一个宏大的产品，我更想把这个小窗口打磨到不碍事、看得清、由人掌控。
