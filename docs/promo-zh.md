# 用量小窗 · 中文文案库

面向掘金 / 知乎 / V2EX / 即刻这类中文渠道。**这不是 `docs/promo-en.md` 的翻译**，两边读者不一样：
英文那边多是从 awesome 列表顺路点进来的路人，要的是"它做什么、不做什么"；中文这边的人愿意读故事，
所以这边讲"为什么会有这么个小窗"。已归并 `docs/community-copy-zh.md` 里仍然有用的部分（该文件保留，
不删）。长文的完整版故事见 `docs/blog-zh.md`。

发任何一条之前先过一遍：

- 一定声明是自己的项目，多短的格式都要写。
- 不编数字：没有 star 数、下载量、用户数可以引用。
- 不说"省钱""再也不会超支"——它不限额、不切模型、不做任何成本承诺。
- 不说是 dsh-cost-meter 的替代品。我们读它的 RPC，它是上游，我们是伴侣。
- 截图要么不用，要么注明「示意图」，真实截图必须先遮掉账号名和余额。
- 不声称已通过任何商店审核。

## 一、掘金 / 知乎 长文（600–900 字）

**标题备选**（第一条为推荐）：

1. 为什么我要在 DSH 里放一个悬浮小窗
2. 订阅看额度，API 看花费：一个只做三家的用量小窗
3. 从一个点不开的按钮开始：用量小窗的迭代记录

**正文：**

很长一段时间里，我在 DSH 里干活的节奏是这样的：写着写着心里一紧——Claude 这个窗口还剩多少？Codex 是不是快到点了？DeepSeek 今天又花了多少？于是开新标签页、翻设置、点几层菜单，看完回来，刚才想写的那句话已经忘了。

信息其实都在，缺的不是数据，是"抬眼就能看见"。所以有了用量小窗：DSH Web 里一个可拖动的小浮窗，把这几样并排放在一处，不用离开当前页面。

### 为什么只做三家

范围就三样：Claude 订阅、Codex（ChatGPT）订阅、DeepSeek API。有人问要不要再加几家，暂时不加。

订阅和 API 本来是两种东西，硬凑一起只会更糊涂。订阅该看用量窗口和重置时间——用了多少、还有多久刷新；它没有"余额"这个概念，我也不打算编一个假的钱数出来。API 该看今天花了多少、账上还剩多少。这两笔账在小窗里始终分开，永远不会加成同一个数字。

支持得越多，每一块越糊。只做三家，我能说清每个数字从哪来、什么时候过期、取不到时显示什么。这比多列几行值钱。

### 它是伴侣，不是替代

小窗自己不联网、不碰凭据、也没有自己的账本。DeepSeek 那部分是从 dsh-cost-meter 的 RPC 读出来的，订阅那部分来自 subscriptions 插件。要用小窗，得先装它们。

所以它不是"更好的 cost-meter"，连当竞品的资格都没有——它是站在别人肩膀上的一块玻璃。上游负责把账算准，功能比我多得多；小窗只做一件事：让你不切走就能看一眼。

### 一个点不开的按钮

最早我挺得意地把窗口做成能缩到角落。缩完自己点了一下，没反应。那一刻很清醒：一个用量窗口，缩小后找不回来，就已经失败了。

后来改朴素了：不另造入口，就是原窗口收起来，留插件名和展开按钮。再后来是四个角——右下角正常，另外三个角布局是坏的，因为我只按最顺手那种摆法做了适配。这些不是想出来的，是用出来的。

### 反馈驱动迭代，不是口号

也因为这些，窗口底部有了一行意见栏。写一句话点发送，浏览器打开一个预填好的 GitHub issue，你按提交它才真的发出去——插件自己一个请求都不发，链接里只有你写的文字和版本号，没有用量、余额和账号名。

每条反馈我都回：采纳，或不采纳并说清原因。采纳的会在下一版 CHANGELOG 里带上 issue 编号。

### 它不做什么

不限额，不会替你拦下任何一次调用；不自动切模型；不承诺省钱。它就是个表盘，判断留给你。目前公开版本验证的是单元测试和打包检查，跨浏览器 UI 我打不了包票。

如果你也在 DSH 里同时用着订阅和 DeepSeek API，欢迎试试，尤其欢迎吐槽四角布局和空闲占用。

项目地址：https://github.com/teethyachi/dsh-usage-mini

## 五、中文里别写的词

| 别写 | 为什么 | 改写成 |
|---|---|---|
| 省钱 / 帮你省下 X% | 我们没有测量过任何花费结果 | 看得见今天花了多少 |
| 再也不会超额 | 我们不做任何拦截 | 看得见距离下次重置还有多久 |
| 替代 dsh-cost-meter | 我们读它的 RPC，它是依赖 | dsh-cost-meter 的伴侣小窗 |
| 已上架 / 官方推荐 | 不是我们说了算 | 从仓库或 tarball 安装 |
| 已有 N 位开发者在用 | 没有这个数字 | 不提采用量 |
| 全平台用量一网打尽 | 只有三家 | Claude、Codex 订阅和 DeepSeek API |
